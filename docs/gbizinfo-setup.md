# gBizINFO接続の準備とWindows設定

## 現在の状態

2026年10月20日、公式サイト https://info.gbiz.go.jp/ へHTTPSで再接続しましたが、クラウド環境のプロキシがCONNECT時点で403を返しました。保存されたネットワーク設定には対象ドメインが存在していますが、この実行環境からの到達は確認できません。これはgBizINFOのAPIキーが不正という判定でも、サービスが有料・無料という判定でもありません。

**公式の最新API仕様・利用条件・料金・申請方法は未確認です。** 旧仕様や別サービスの仕様を推測して実装せず、外部APIへの通信を停止しています。次が確認待ちです。

| 確認対象 | 確認内容 | 現状 |
| --- | --- | --- |
| API仕様 | 現行バージョン、接続先、認証方法、検索パラメーター、返却項目、ページング、制限、エラー | 未確認 |
| 利用条件 | 法人営業利用、CRMでの保存、CSV出力、出典表記、第三者権利、保持期間・更新条件 | 未確認 |
| 料金 | 現行APIの利用料、無料の条件、件数・頻度制限 | 未確認。費用はまだ発生させていない |
| 申請 | 利用申請の入口、登録情報、審査、キーの発行・更新・失効方法 | 未確認 |

前の提案の「無償提供の政府APIとしての候補」は最新条件を確認した結果ではありません。公式の現行案内を確認するまで、無料と断定しません。

## 実装した範囲

- リサーチ画面 → 自分のアプリのAPI `/api/research/gbizinfo` への接続
- GETでキーが設定されているかだけを確認し、値・一部・文字数を返さない
- POSTで全国／47都道府県、業種キーワード、企業名キーワードを受け取り、形式を検証
- APIキー未設定はKEY_MISSING、キー設定済みでも仕様確認前はDOCUMENTATION_PENDINGとして停止
- サンプル企業を結果として返さない。取得失敗時のサンプルへのフォールバックもない
- 設定状態や応答をキャッシュしない。キー・検索結果をlocalStorageへ書き込まない
- Google Placesは保留。営業リスト、ロゴ、保存済み企業、履歴、下書きは変更しない

**アプリ内APIへの接続は実装済みですが、gBizINFO実APIへの接続は未完了です。** まだキーを入れるだけで企業検索が動く状態ではありません。`lib/server/gbizinfo.ts` の仕様確認フラグは開発者による公式資料の確認後に変更するものです。ユーザーが強制的に書き換える手順はありません。

業種等の検索条件が現行gBizINFOのどの条件に対応するかも未確定です。入力画面は準備済みですが、APIが対応しない絞り込みを対応済みとは表示しません。データ取得後も不明な業種・公式サイト・従業員数は推測で補完しません。

## ユーザーが行う次の操作

まずWindowsのブラウザーで https://info.gbiz.go.jp/ を開いてください。公式サイト内のAPI利用案内・開発者向け資料へ進み、上の表の資料を確認します。画面名や申請方式は確認できていないため、具体的なボタン名や申請期間は断言しません。

このクラウド環境への設定追加はすでに行われています。同じ許可先を繰り返し追加する必要はありません。公式資料をこちらから読めない場合は、次のいずれかで開発を再開できます。

- 設定が実際に反映された実行環境から公式資料へ到達できるようにする
- Windowsでダウンロードした公式のAPI仕様書（OpenAPI JSON/YAML、PDF等）と利用条件・料金・申請の案内をGitHubの作業ブランチの `docs/gbizinfo-official/` へアップロードする。取得元URL・取得日も添える。第三者への共有が認められた公開資料に限り、キー・個人情報・非公開の申請画面はアップロードしない

資料を確認後、現行仕様のサーバーアダプター、結果の正規化・出典表示、登録制約を実装し、申請が必要ならその時点で公式の実際の手順を案内します。発行済みキーがある場合でもキーそのものをチャットへ送らないでください。

## Windowsでキーを設定する手順（公式手順で発行された後）

### 1. コードを更新

起動中のターミナルでCtrl+Cを押します。Gitで取得した場合はpackage.jsonのあるフォルダーで次を実行します。ファイルを自分で編集している場合は、上書き・強制リセットをせずに変更を保存してください。

```powershell
git switch feature/dswitch-sales-ai
git pull --ff-only origin feature/dswitch-sales-ai
npm.cmd ci
```

ZIPの場合はGitHubのfeature/dswitch-sales-aiブランチ → Code → Download ZIPで取得し、以前のフォルダーを残して別フォルダーへ展開します。package.jsonのあるフォルダーで右クリック →「ターミナルで開く」を選び、`npm.cmd ci`を実行します。

### 2. .env.localを作成・編集

package.jsonと同じフォルダーで、次を実行します。

```powershell
notepad .env.local
```

既存ファイルがあれば消さずに次の1行を追加します。同じ名前がある場合は重複追加せず、既存の行を修正します。

```dotenv
GBIZINFO_API_TOKEN=ここをご自身のキーに置き換える
```

ここにある文は見本です。この文をそのままキーとして使わないでください。`.env.example`にも見本がありますが、本物のキーはそちらに書かないでください。

メモ帳で新規保存する場合は「ファイルの種類」を「すべてのファイル」にします。エクスプローラーの表示設定でファイル名拡張子を表示し、ファイル名が`.env.local.txt`ではなく`.env.local`であることを確認します。

`.env.local`は.gitignoreで除外されています。強制追加（git add -f）はしないでください。キーを画面写真・チャット・GitHubへ載せないでください。誤って公開したら、公開箇所を消すだけでなく、公式サービス側でキーを失効・再発行してください。

`NEXT_PUBLIC_`を付けるとブラウザーに公開する設定になるため使用しません。本実装ではGBIZINFO_API_TOKENはサーバーのroute handlerだけが読みます。

### 3. 再起動して接続状態を確認

```powershell
npm.cmd run dev -- --hostname 127.0.0.1
```

表示されたLocalのアドレスをCtrlを押しながらクリックし、サイドメニューの「AI企業リサーチ」→「接続状態を再確認」を押します。

- 未設定：ファイルの位置・拡張子・変数名、再起動したかを確認
- 設定あり（有効性は未検証）：サーバーが値を読み取れた状態。gBizINFOがそのキーを受け付けることはまだ未検証
- 仕様確認待ち：公式資料の確認と実APIアダプター実装が必要。キー再発行を繰り返さない

APIキーはファイル変更だけでは読み込まれないことがあります。必ずサーバーを停止・再起動します。試験中は自分のPCの127.0.0.1に限定し、本番公開は行いません。既存の営業データを保つため、以前と同じブラウザー・同じアドレスで開き、サイトデータを削除しないでください。

## 今後、実APIで確認すること

公式の手順・条件・料金を確認し、利用者の設定が完了した後に少件数の検索を実行します。キー不正・利用制限・タイムアウト・仕様変更・0件を区別し、検索結果の企業名・所在地・出典が実応答に対応することを確認します。実API検証が終わるまでは接続完了とは報告しません。
