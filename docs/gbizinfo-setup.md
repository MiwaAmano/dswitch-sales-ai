# gBizINFO API v2 — Windowsでの設定と接続テスト

## 実装済み

画面からNext.jsサーバーを経由して、実際のgBizINFO API v2へ検索・詳細取得を行うコードを実装しています。以前の「公式仕様確認待ちで常に停止する」処理は解除しました。ただしこの環境にユーザーのトークンはなく、実トークンでの疎通確認はWindows側で必要です。検索失敗時にサンプルへ切り替えることはありません。

- 検索：GET `https://api.info.gbiz.go.jp/hojin/v2/hojin`
- 詳細：GET `https://api.info.gbiz.go.jp/hojin/v2/hojin/{corporate_number}`
- 認証：サーバーのHTTPヘッダー `X-hojinInfo-api-token`
- 設定：`.env.local` の `GBIZINFO_API_TOKEN`。`NEXT_PUBLIC_`は使用しません
- 法人名：`name`による部分一致
- 都道府県：`prefecture`に01〜47の都道府県コード
- `page`は1〜10、`limit`は10。自動全件取得・自動ページ巡回・自動リトライなし
- メタデータも要求し、APIに元データの出典が収録されていれば項目別に保持・表示します。
- 検索応答は`hojin-infos`配列。検索で法人番号・名称・所在地、詳細で業種配列・企業ホームページ・従業員数・事業概要を取得
- 検索1ページにつき最大11 APIリクエスト（検索1回＋最大10社の詳細）、詳細は最大3件並列、全体25秒で中断

### 仕様参照の確認範囲

公式案内は https://content.info.gbiz.go.jp/api/index.html です。このクラウドでは同ホストへのHTTPS接続がプロキシのCONNECT時点で403となり、最新ページを直接取得できていません。代替として、次の第三者公開リポジトリに保存されたv2 OpenAPIスキーマと実装例を参照しました。**公式ページを直接読めたという意味ではありません。**

- v2 OpenAPIの写し：https://github.com/koizumikento/gbizinfo-mcp/blob/f008e3cb1717d7d56990e833fcb66c88e4f259af/docs/openapi.json
- 公開実装の説明：https://github.com/koizumikento/gbizinfo-mcp/blob/f008e3cb1717d7d56990e833fcb66c88e4f259af/README.md

実装は上記の仕様参照に基づき独自に作成しました。公開の動作確認用トークンは利用せず、ユーザーのトークンをコードへ埋め込んでいません。最新仕様との差異があれば、後述のエラーとして確認して修正します。

### 業種での絞り込み範囲

参照したv2検索仕様には、業種そのものを指定する検索パラメーターがありません。存在しないパラメーターを送るのではなく、取得した10社の詳細の`industry`と`business_summary`へ部分一致で絞り込みます。業種コードはAPIの返却表記のまま表示し、未確認のコード表で業種名を作りません。業種情報のない企業は一致に含みません。

そのページが0件でも、全国で0社という意味ではありません。次ページも確認するか、業種条件を外してください。都道府県のみの検索も可能です。全国検索の場合は法人名を指定してください。全国の全法人から業種だけで網羅検索する機能は未実装です。

## 1. Windowsのコードを更新

起動中のターミナルでCtrl+Cを押します。Gitで取得している場合は、package.jsonがあるフォルダーで次を実行します。

```powershell
git switch feature/dswitch-sales-ai
git pull --ff-only origin feature/dswitch-sales-ai
npm.cmd ci
```

自分で編集したファイルがあって更新が止まる場合は、強制上書き・リセットをせず、エラーメッセージだけを共有してください（キーや.env.localの内容は共有しないでください）。

ZIPで取得した場合はGitHubのfeature/dswitch-sales-aiブランチ → Code → Download ZIPで再取得します。以前のフォルダーを残して別フォルダーに展開し、package.jsonがある場所で右クリック →「ターミナルで開く」→`npm.cmd ci`を実行します。古いフォルダーの.env.localは自動では引き継がれません。次の手順で新しいフォルダーに設定します。

## 2. .env.localへトークンを保存

package.jsonがあるフォルダーで次を実行します。

```powershell
notepad .env.local
```

既存ファイルは消さず、次の行を追加または修正します。同じ変数名を重複登録しないでください。

```dotenv
GBIZINFO_API_TOKEN=ここをご自身のAPIトークンに置き換える
```

見本文字ではなく、gBizINFOで発行されたAPIトークンそのものを右側に入れます。前後の空白や途中の改行を入れないでください。新規保存時はファイルの種類を「すべてのファイル」とし、ファイル名が.env.local.txtになっていないことを確認します。`.env.example`に本物のトークンを書かないでください。

.env.localは.gitignoreで除外されています。GitHubへのアップロード、git add -f、チャットへの貼り付けは行わないでください。誤って公開した場合はgBizINFO側で失効・再発行してください。サーバーはトークンの値や外部サービスの生のエラー本文を画面へ返しません。

## 3. アプリを起動

```powershell
npm.cmd run dev -- --hostname 127.0.0.1
```

Readyが表示されたら、ターミナルのLocalのアドレスをCtrlキーを押しながらクリックします。設定変更後は必ずCtrl+Cで停止してから再起動してください。別のアプリが3000番を使っている場合は元のアプリを停止し、以前と同じアドレスで使います。ブラウザーの保存データはアドレスにひもづくためです。

## 4. 接続テスト

1. 左メニュー「AI企業リサーチ」を開き、「接続状態を再確認」を押す
2. 「APIトークンを読み込みました」が表示されることを確認（この段階では有効性の確認はまだ）
3. 初回は法人名の一部を入力し、業種を空欄にして「企業を検索」。必要なら都道府県を指定。例として「トヨタ」など実在法人名を使用できるが、特定の結果件数を保証するものではない
4. 企業名・法人番号・所在地・取得元・取得日時を確認。従業員数やサイトが収録されていなければ「未取得」と表示される
5. 「営業リストに登録」を押し、営業リストで企業名を検索。未接触・優先度中で追加され、詳細の備考に出典があることを確認
6. 詳細からメール作成へ進む。従業員数が不明なら人数を記載しない。メールは下書き保存のみで送信されない
7. 営業進捗画面でステータスを更新し、履歴とフォローアップが従来どおり使えることを確認

トークンそのものを返す接続確認コマンドはありません。画面に設定ありと出ても、実APIの検索成功までは認証成功としません。

## エラーの見方

| 表示 | 確認すること |
| --- | --- |
| KEY_MISSING | ファイル名・配置・変数名・アプリの再起動 |
| TOKEN_FORMAT | トークン中の空白・改行・全角文字。正しい値をローカルで確認し、チャットへ送らない |
| AUTH_FAILED / 401 | トークンの有効性・コピー漏れ・失効・再発行状況 |
| ACCESS_DENIED / 403 | 利用権限、ネットワークの接続許可、プロキシ、サービス側の制限。トークン不正とは限らない |
| RATE_LIMIT / 429 | API制限。時間をおき、短時間の連続検索を控える。自動再試行なし |
| SEARCH_BUSY | このサーバーで前の検索が実行中。完了後に再試行 |
| NETWORK_ERROR | api.info.gbiz.go.jpへのHTTPS接続、PCのインターネットやセキュリティ設定 |
| TIMEOUT | 25秒以内に完了しなかったか中断された。条件を絞り再試行 |
| ENDPOINT_NOT_FOUND / INVALID_RESPONSE | サービスの障害・応答形式・API v2の仕様変更 |
| API_REJECTED / UPSTREAM_QUERY | APIが条件・認証等を受け付けなかった。条件を減らして再試行。生の応答は秘密情報の漏えい防止のため画面に出さない |
| 一部の詳細が未取得 | 名称・所在地は検索応答から表示。取得できなかった詳細は推測しない。再検索や公式サイトで確認 |
| 0件 | 条件を減らす。業種指定がある場合はこのページ内の0件であり、全国の0件ではない |

エラーを共有するときは画面のエラーコードとメッセージ、検索条件だけにしてください。トークン、.env.local、認証ヘッダーは共有しないでください。

## 保存・利用条件・料金

登録ボタンを押した企業だけをlocalStorageの既存のdswitch-sales-v1へ追加します。既存企業、履歴、下書きを消去する移行はありません。法人番号が一致する企業は重複追加せず、番号がない既存データについては同名企業も登録済み扱いとします。別法人の同名企業も保守的にブロックするため、既存データを確認してください。既存企業の更新・統合は自動で行いません。

出典・取得日時・法人番号と項目別の取得情報を保存します。登録したデータの従業員数欠損はnull、業種等の欠損は空欄とし、架空の値を埋めません。CSVは従来の列構成を維持し、欠損人数を空欄にします。備考に出典は含まれますが、法人番号の構造化情報・項目別出典・履歴・下書きをCSVから完全復元することはできません。CSVから再登録したレコードの法人番号照合は失われるため、同名確認を併用します。

APIの応答全体やトークンはブラウザーへ渡さず、検索結果は画面の一時状態にのみ保持し、登録前の結果は画面を離れれば破棄します。個人の代表者氏名など営業管理に不要な項目は取り込みません。メール・電話・自動営業は実行しません。

ご本人が利用登録時に同意した現行条件で、法人営業用途、取得情報の保存、CSV出力、出典表記、第三者権利を確認してご利用ください。公式の料金・規約ページをこのクラウドから直接参照できていないため、最新の料金条件を無償と断定しません。利用量は検索1ページあたり最大11リクエストです。Google PlacesやAIの有料サービスは利用しません。

API案内：https://content.info.gbiz.go.jp/api/index.html
API・データダウンロード利用規約：https://help.info.gbiz.go.jp/hc/ja/articles/4999421139102
利用規約：https://help.info.gbiz.go.jp/hc/ja/articles/4795140981406

この試作品にはログイン・共有DB・永続的な利用量カウンターがありません。Windowsで127.0.0.1に限定して起動し、公開・共有する前には認証とアクセス制御・利用量管理を追加してください。サーバーの同時検索1件制限は単一プロセス内のみで、公開APIの悪用防止や正式な課金上限の代替ではありません。

## 検証済みと未検証の区別

- 自動テスト：v2のURL・ヘッダー・都道府県コード、検索→詳細、欠損、各エラー、登録・重複・CSV・メール、既存機能
- ブラウザー：ローカルのテスト専用プロセスで外部fetchを模擬し、画面→Next.js route→v2形式の応答→登録→メール・進捗を検証。サンプルを本番検索に組み込む仕組みはない
- 実際のgBizINFO応答・ご本人のトークン：このクラウドでは未検証。上のWindows接続テストで確認する
