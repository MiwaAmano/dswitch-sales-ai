# d switch向け営業リサーチ・採点

## 取得範囲

gBizINFO API v2の接続先、トークンのサーバー側利用、法人名・都道府県による検索を維持します。1ページ10社、ページ番号は参照しているv2仕様の範囲で1〜10。ページ送りは手動で、全ページの自動巡回は行いません。全国を選んでも全法人を網羅する検索ではありません。

画面には検索時の法人名・都道府県・ページ、API取得件数、業種条件後の件数、人数・ランク適用後の表示件数、取得日時を表示します。最後のページや絞り込み後が0件でも「全国で0社」とは表示しません。APIが10件返した場合は、次ページが存在する可能性として次へ進めます。次ページが0件になることもあります。

既存の業種／事業概要キーワードは取得ページの詳細で部分一致検索します。人数・ランクの絞り込み、スコアの並び替えは、その取得済みページだけに適用します。人数の絞り込みを変更してもAPIへの追加リクエストは行いません。APIに未確認のパラメーターを追加していません。

## 業種の表示

APIが返したindustry配列をindustryValuesにそのまま保持します。既存レコードの配列がない場合は従来の取得表記を読み取ります。

現時点で、この環境ではgBizINFO公式ページ／ヘルプにHTTPS接続するとプロキシで403になり、gBizINFOの業種コード体系・対応表を確認できませんでした。そのため**有効化したコード→名称対応表はありません**。Gや39、3911といった表記を、形だけで日本標準産業分類等と決めつけません。

- APIが日本語名を返した場合：取得した日本語表記をそのまま表示（独自のコード翻訳ではない）
- コードしかない場合：「業種未確認（コード：取得値）」
- 業種がない場合：「業種未確認」

未確認コードは業種親和性と業種名の充実度に加点しません。日本語の業種名を取得できても、業種から実際のデスクワーク比率を断定しません。将来公式コード表を確認できた場合に、出典・版・対応範囲を明示して対応表を追加する設計です。

## 採点ルール

ルール版：dswitch-office-snacks-v1。株式会社tenのオフィス向け駄菓子福利厚生サービスの営業先に優先順位を付ける、説明可能な試作ルールです。AI APIや外部の推論サービスは使いません。未取得項目を推測で埋めず、未取得分の配点を他の項目へ振り替えません。

| 項目 | 上限 | 基準 |
| --- | --- | --- |
| 業種の親和性 | 35 | API取得の日本語名が情報通信業、金融業・保険業、学術研究・専門・技術サービス業なら35点。不動産業・物品賃貸業、卸売業・小売業、教育・学習支援業なら20点。その他・未確認は0点。複数業種は最高点を採用し合算しない |
| 従業員規模 | 30 | 20〜299名：30点、10〜19名／300〜999名：22点、1,000名以上：15点、1〜9名：10点、0名／不明：0点 |
| 事業内容の親和性 | 20 | 取得した事業概要にソフトウェア・システム開発・情報処理・コンサルティング・デザイン・広告・事務・研究・受託開発がある場合、異なる一致語ごとに10点、上限20点。企業名や未取得の概要から補完しない |
| 企業情報の充実度 | 15 | 企業名・所在地・日本語の業種名・従業員数・公式サイトの情報があれば各3点。既知の従業員0名と不明は別に扱う |

上の業種名は営業仮説のルールであり、gBizINFOのコードをその日本語名へ翻訳するための表ではありません。取得済みの日本語表記との一致だけを判定します。人数帯もサービスの正式な利用条件・最低発注数・推奨人数を表すものではありません。

事業内容の得点はあくまで文面の一致です。否定表現や文脈を意味解析していないため、「ソフトウェアを含む」と表示しても、実際の働き方や職場構成を確認したとは扱いません。

- A：80〜100点
- B：60〜79点
- C：0〜59点

各社に総点・ランク・4項目の点数／上限・理由・未確認項目を表示します。成約確率やサービス導入可否ではありません。デスクワーク比率、出社率、福利厚生の導入状況は常に未確認で、推測加点しません。情報不足によるCランクは不適合を意味しません。

## 絞り込み・並び替え

従業員数は「すべて」「不明のみ」「取得済みのみ」「0〜9」「10〜19」「20〜49」「50〜99」「100〜299」「300〜999」「1,000名以上」を選べます。不明を0名に変換しません。ランクA/B/Cでの絞り込みと、スコアの高い順／低い順／API取得順に対応しています。同点はAPI取得順を維持します。いずれも現在のページ内のみです。

## 登録と既存データ

登録時には取得情報、総点・内訳・理由・ルール版を保存します。営業優先度の初期値はA→高、B→中、C→低です。これは新規登録企業だけの初期値で、営業リストから手動変更できます。既存企業の優先度・情報・履歴・下書きは更新しません。

法人番号の一致で重複を防ぎます。法人番号を持たない旧レコードは同名も保守的に登録済み扱いにします。既存のlocalStorageキーは変えず、削除・再作成する移行はありません。業種未確認や人数不明を、営業メールに確認済みの業種・人数として挿入しません。

## CSV

「表示中の企業をCSV出力」は現在のページの人数・ランク絞り込みと並び順を反映します。非表示企業や未取得のページは出力しません。UTF-8 BOM付きで、Excel向けの数式対策とカンマ・引用符・改行のエスケープを行います。

企業名、法人番号、所在地、業種表示、業種の取得表記、従業員数、公式サイト、総点、ランク、4項目の点数、評価理由、注意事項、取得元、元データの出典、取得日時、ルール版を含みます。トークンは含みません。

これは比較・確認用のリサーチ専用CSVです。従来の営業リスト用CSVと列構成が異なり、そのまま営業リストのCSVインポートへ渡す用途ではありません。営業リストへの追加は登録ボタンを使ってください。営業リスト側のCSVは従来の列構成を維持し、備考に登録時のスコア・出典が含まれます。いずれも履歴・下書きの完全なバックアップではありません。

## Windowsで最新版を起動

1. 起動中のターミナルでCtrl+Cを押す
2. Gitの場合、package.jsonのあるフォルダーで次を実行する（ローカル変更があれば強制上書きしない）

```powershell
git switch feature/dswitch-sales-ai
git pull --ff-only origin feature/dswitch-sales-ai
npm.cmd ci
npm.cmd run dev -- --hostname 127.0.0.1
```

ZIPの場合はGitHubでfeature/dswitch-sales-aiブランチを開き、Code → Download ZIPで取得します。以前のフォルダーを残し別の場所へ展開して、package.jsonのあるフォルダーでターミナルを開きます。新しいフォルダーにもご自身の.env.localを安全に配置し、npm.cmd ci、npm.cmd run dev -- --hostname 127.0.0.1を順に実行します。

.env.localのGBIZINFO_API_TOKENは変更不要です。GitHub・チャットには送らないでください。同じ端末・ブラウザー・アドレスで開き、Ctrl+F5で再読み込みします。既存データを残すためサイトデータは消さないでください。

AI企業リサーチで法人名または都道府県を入力して検索し、件数の範囲を確認 → 人数・ランク・並び順を選択 → 内訳を確認 → CSV出力または営業リストに登録、の順で使えます。APIキーがない場合は設定案内が表示され、サンプルを実在企業として出力しません。

## 検証範囲

npm test、npm run typecheck、npm run buildを実施します。採点の配点・ランク境界・人数帯・未確認コード・欠損・CSV・登録・重複・既存機能をテストします。ブラウザーではテスト専用の模擬v2応答を使い、並び替え・人数フィルター・CSVダウンロード・登録・データ保持・ページ送り・モバイル・メールを確認します。

ご本人のAPIトークンによる実API検索はこの環境では未検証です。v2の既存リクエスト方式は維持し、今回はAPIに新しい検索条件を追加していません。APIの最新の規約・料金は利用登録時の公式案内に従ってください。
